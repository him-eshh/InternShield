InternShield app map

InternShield turns a recruiter or job message into a source-linked risk report. Tailor and Practice continue from that role, while Tracker and Profile keep optional local context.

This is a reference route through the current code. It does not claim that the owner has completed the guided code tour or final hands-on review.

One action through the app

  1. 1 · Enter a messageCheckForm.submit() validates the input and passes it to App.onCheck().
  2. 2 · Check the evidencerunPipeline() gathers quoted facts and optional lookups. score() applies fixed risk rules.
  3. 3 · Review and refineReportBody shows the score, evidence, and missing checks. A quick answer runs score() again.

Three stops in the source

  1. Input → components/CheckForm.tsxSearch for messageIssue and submit. The form rejects unusable input, then sends the message, sender, company, and example state to App.onCheck in components/App.tsx.
  2. Checks and rules → lib/client/pipeline.tsSearch for runPipeline. It calls the extraction and lookup routes, tracks failed or skipped checks, and passes the gathered facts to score in lib/scoring/score.ts. The AI supplies candidate facts; fixed rules decide the score.
  3. Visible result → components/report/Report.tsxSearch for ReportBody and onAnswer. The report shows source quotes, risk and coverage separately, then recalculates when the user answers a quick question.

To change this, start here

Form rules or example buttons: CheckForm.tsx, then the relevant UI tests.

Risk flags or weights: rules.ts and score.ts; check score.test.ts and the labeled evaluation.

Unavailable lookup behavior: pipeline.ts and coverage.ts.

Report wording or layout: Report.tsx and the smaller components in components/report/.

A practice to reuse

The PRD asks for an evidence-based risk report. The score rule tests cover high-risk and ordinary examples, missing lookups, and quick answers. When changing a rule, state the visible result first, add a case to score.test.ts or the evaluation set, then verify the report still explains the same evidence. That keeps a model-generated fact from silently becoming a model-generated verdict.

Run it again

From the repository root, run npm install, copy .env.example to .env.local, set the server keys described in the README, then run npm run dev and open http://localhost:3000. The built-in suspicious offer is fictional.
