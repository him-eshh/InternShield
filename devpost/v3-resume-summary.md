## Known limits / choices

- Word supports shortening with existing words, not arbitrary paraphrases. PDF is offered for broader wording; this constraint is visible before upload/review and on rejected manual edits.
- PDF cover/redraw keeps the old text layer underneath, as anticipated by the brief. Plain-text export supplies a clean text layer; this is not redaction. Covers are white, not sampled from colored backgrounds.
- Closest standard PDF fonts are used. Unencodable characters cause the edit to be dropped/rejected rather than corrupting the text.
- DOCX HTML preview strips active links/images and retains link text. It is a content preview; actual Word export was validated separately.
- Requests are bounded to 10,000 resume characters, 2,000 posting characters and bounded geometry, within the existing shared body limit. Very geometry-heavy inputs can hit that shared limit.
- Preparing PDF combinations adds real work to the layout-check step (at most 64 valid subsets for six edits), so later accept/reject actions can remain instant. Preparation is cancellable and publishes no partial cache.
- The optional Word QA requires existing configured Windows Word. Cold startup was slow; corrected COM calls use `[ref]` arguments and .NET strings. It is not a runtime dependency or a cloud API.
