InternShield

One Next.js site. The browser shows everything and runs the scoring rules; five small server routes do the outside calls and hold the keys. No database, no accounts, free plans only.

The shape

Blue boxes are code you write. Dashed boxes are outside services on free plans with no card. Page text from searches never goes to Groq; only links and website names do.

How the checklist steps run (and fail)

Pick a scenario to see what each step ends as. Every step returns exactly one of three shapes: done, failed, or skipped, so nothing can crash the run.

    Components, by PRD behavior

    Fact extraction & safety
    • app/api/extract: Groq strict JSON schema, one non-streamed call, retry once
    • lib/quotes.ts: drops any fact whose quote isn't really in the message
    • lib/scoring/backstop.ts: keyword scan of raw text, unioned with the facts
    • app/api/explain + explainFallback.ts: flags only, banned words, fallback text
    Risk scoring
    • lib/scoring/score.ts: critical floor 85 → add points → good signs (max −20) → clamp → level
    • rules.ts: every weight in one constant
    • domains.ts: free email, hiring platforms, lookalikes, exact university match
    • patterns.ts, level.ts, coverage.ts
    Model fallback & token budget
    • Limits are per model: extract tries 20b → 120b, explain tries 120b → 20b
    • On 429 or near-zero remaining headers, mark the model "resting" and switch; show the limit message only when both are out
    • Tiny prompts: ~60-word extract instructions, tight schema (short names, fixed kinds, no descriptions), message sent once and trimmed
    • Explain gets level + ≤6 "title | quote" lines, ~250 max tokens. Target ~2,400 tokens per check, measured on day one
    Quick questions
    • questions.ts: asked only if unknown and score-changing
    • Outside the US? · Where did it come from? · Signed an offer? · Had an interview?
    • Answering re-runs score() in the browser, so there's no server trip
    Sender & website checks
    • /api/sender: RDAP creation date (cached 7 days), MX via Google/Cloudflare DNS, Hunter Email Insight if a key exists
    • Phone → country with libphonenumber-js
    Real-posting lookup
    • /api/company: Tavily "<company> careers" → official website (code picks, not AI)
    • /api/posting: Tavily on official site + Greenhouse/Lever/Workday/Ashby
    • Details come from the result title and snippet; "not listed" if absent
    Report & outcomes
    • components/report/*: ring, quick questions, explanation, 3 groups, cards, Couldn't check
    • ScamOutcome: what to do now, FTC / IC3 / platform, Copy report
    • PostingSection: expanding card, match table, apply button
    Profile & resume
    • ProfileSteps.tsx + storage.ts (is:profile, is:resume, is:theme)
    • resume.ts: PDF (pdf.js) or Word (mammoth) → text, in the browser only
    Usage guard
    • Origin must match ALLOWED_ORIGINS; body < 8 KB; message ≤ 4,000 characters
    • Per visitor 3 checks/min, 20/day; global 120 checks/day (both gpt-oss models ≈ 400K tokens/day at ~2,400 tokens/check)
    • Tavily cap 80 credits/day. Search credits are the tighter limit; when they're reached, the company and posting checks go to Couldn't check
    • In memory, per instance, best-effort; the free-plan no-card rule is the real net
    • Example snapshots keep both examples working if limits run out
