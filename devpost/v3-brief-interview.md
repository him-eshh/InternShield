- A fresh session reads: the progress file first, then only the brief sections it needs, `git log --oneline v3-base..HEAD`, `git status`. Grep the research section you need instead of re-reading whole files.
- Save usage: short tool output. `npx vitest run --reporter=dot` (rerun only failing files), pipe long output through `tail -n 40`, read files with offset/limit, look at screenshots selectively but DO look at them (quality is the point of v3).
- Subagents run on Sonnet (forced). Give each a precise, self-contained task with exact files and acceptance checks; ask for a report of 10 lines or fewer.

## Why v3 exists (Himesh's verdict on v2, Oct 25, 2026)
He tested v2 by hand. The scoring logic works. Everything else fell short: the tailored resume was too long, lost the original format and read as AI-written ("it will get rejected"); no loading state, no preview before download, no way to adjust and see changes. No nav bar, no home screen, no profile screen, no icons; very hard to navigate; unclear how to build the profile; flows dropped him back into the questions. Answers/details he added showed no visible effect ("no score impacted" is a dead end). The UI looked basic and AI-generated, only black and blue, unresponsive, no motion. The interview showed only one question. v2's checks only proved things rendered; **v3 is judged on whether it is actually good to use.** Every brief has a Quality bar: treat each line as a test you must pass and prove with a screenshot or an automated check.

## Design system (approved by Himesh on Oct 25, final; tokens live in ONE swappable theme file, `app/theme.css`)
Himesh rejected v2's "Calm Instrument" one-blue look (findings 06 §2 Direction A and its "no gradients / one accent" rules are REPLACED by this section; 06 §4 motion specs, §9 craft checklist, §10 accessibility and §15 pitfalls other than the color rules still apply).
- **References:** Linear (polish, motion, dark elevation from one hue), Raycast (vivid per-command color, crisp icons), Duolingo (session flow, progress bars, end-of-session moment), Notion (home and onboarding clarity). Name these in code comments of `app/theme.css`, not in the UI.
- **Tool color identities**, carried through each tool's icon, nav tab (active state), primary buttons, focus/highlights and illustration: **Check = warm coral**, **Tailor = green** (lean emerald/teal so it never reads as the risk "low" green), **Practice = violet**. Tracker and Profile use the ink/neutral brand color. Each accent has light + dark values, a soft tint (backgrounds) and an on-accent text color, all WCAG AA (text >= 4.5:1, UI marks >= 3:1).
- **Risk colors are reserved:** red (high), amber (medium), green (low) appear only on risk results (ring, level icon, tags, marks), always with an icon + words, never color alone. Coral must be visibly distinct from risk red (more orange/pink, lighter); if a report screen shows both, the report's chrome uses neutral, not coral.
- **Canvas:** warm off-white light theme (e.g. #FBF8F3 page, white cards, warm grey borders). Dark theme: deep ink-navy (e.g. #0D1220 page with 3-4 elevation steps derived from one hue), never pure black, no shadows in dark (use surface steps).
- **Type:** Bricolage Grotesque (display, headings; next/font/google, OFL) + Inter (body, UI; next/font/google). Tabular numbers on scores, counters, timers.
- **Depth and texture:** cards with gentle layered shadows (light theme), soft gradient mesh only in the home hero (and optionally faint on empty states), no glow borders, no blurred blobs everywhere, no emoji bullets.
- **Icons:** lucide-react only (one stroke width, 1.75 or 2 everywhere). **Illustrations:** one small hand-made SVG illustration per tool (Check, Tailor, Practice) plus one for Profile/empty states, drawn in the tool's colors, used on Home and empty states. Inline SVG components, no stock art, no AI-generated images.
- **Motion (motion/react, `MotionConfig reducedMotion="user"`):** page transitions between tabs (fast crossfade + 8px slide, <= 250ms), staggered card reveals on Home and lists (once, on mount; never scroll-reveal), score ring counts up on reveal, changed resume lines glow briefly when accepted/rejected, interview per-round progress bar, a small end-of-session celebration (tasteful, <= 1.2 s, no confetti flood; skip under reduced motion), hover/press states on cards and buttons. Under reduced motion everything is immediately in its final state.
- **Responsive:** designed (not just squeezed) at 390, 768 and 1440. Mobile: bottom tab bar with icons + labels, 44px touch targets, no sideways scroll at 320. Desktop: top nav (or left rail) with icons + labels; content widths that suit each screen (coding layout wide, forms narrow).
- **Copy:** short, second person, specific, verb first. No filler ("Unlock", "Supercharge", "Seamless"), no fake stats.

## Items (commit each)
I1. **Question bank from real public sources (no generation-only).**
   - Find public, permissively licensed GitHub datasets of company-tagged LeetCode problems (e.g. company-wise lists with title, difficulty, link, frequency/tags). Use ONLY repos whose license allows reuse (MIT, Apache-2.0, CC0/CC-BY, Unlicense); record repo URL, commit SHA, license and retrieval date in `data/question-bank/SOURCES.md`. Fetch raw files from GitHub over plain HTTPS (no login, no LeetCode site scraping, no API keys). If no suitably licensed dataset is found, log it as Pending Himesh and build the bank from a hand-curated list of well-known problem titles + public LeetCode URLs + difficulty + tags (facts, not copied statements).
   - Store only metadata: `BankQuestion { id, title, difficulty, url (leetcode.com/problems/<slug>/), tags, companies, source }` in `data/question-bank/*.json` (compact; aim for a few thousand entries max, size < 2 MB total, loaded lazily or server-side). **Never copy problem statements**; the UI links out to LeetCode for the full statement and the session asks the user to explain approach, complexity and code.
   - Filters: company, role (SWE/frontend/backend/data/ML map to tag sets), difficulty (Easy/Medium/Hard, and "mixed"), topic tags. Hard problems included.
   - Keep the app's own runnable problems (`problems.ts`, SQL, debugging) for rounds that execute code (Python, TypeScript, SQL in the browser with tests); bank questions are for approach/code discussion rounds graded by the model with a rubric. Tests for loader + filters.
I2. **Company research shapes the session.** On setup, if a company is given, call `/api/intel` (`kind: "interview"`; cached, capped; Wikidata/official pages first, never LinkedIn/people sites) to get the round mix and behavioral themes (e.g. company values/leadership principles from official pages). Show "How <company> interviews" as a short card with source links; use it to pre-select rounds and to seed behavioral questions (STAR prompts tied to the cited values). Combine with the existing company presets ("-style", never implying affiliation). Fallback when limited: presets only, one line saying so.
I3. **Session setup screen (Practice violet identity, theme tokens, lucide icons).** Pick: round types (multi-select cards: coding, SQL, debugging, system design, behavioral, recruiter screen, case, portfolio/take-home discussion), topics (chips from bank tags) and optional custom questions (the user types their own questions; they are asked verbatim), difficulty (Easy/Medium/Hard/Mixed), company (+ preset), role, language (Python, TypeScript, SQL run in browser; Java/C++/Go/JavaScript allowed for discussion/code review only, no execution, say so), and **session length: N questions or N rounds** (e.g. "5 rounds"), with sensible defaults (5 questions). Clear primary button "Start session". Profile prefill (role, company targets) if present.
I4. **Continuous session engine** (`lib/tiers/session.ts`, pure and unit-tested, + UI): loop question -> answer (text, code editor, or voice where it exists today) -> feedback (code-first checks where possible, then rubric feedback from the model: what was good, what was missing, one concrete improvement) -> optional follow-up (the interviewer asks 0-2 follow-ups per question based on the answer, e.g. complexity, edge cases, "what if the input is 10x larger", STAR gaps) -> next question. Questions never repeat within a session; difficulty can adapt (Mixed: step up after a strong answer, down after a weak one). Controls: Skip, Hint (costs a note in the scorecard), "End session" (early stop, confirm). **The session ends automatically after the chosen number of questions/rounds** and shows the summary. State persists across refresh (localStorage) so a reload resumes the session.
I5. **Progress + summary.** Per-round segmented progress bar ("Question 3 of 5", round labels), animated fill (reduced-motion aware). End screen: overall scorecard (reuse the 4-area scorecard, extended per round type), per-question recap with feedback and links (LeetCode links for bank questions), strengths, top 3 things to practice next, "Practice these again" (starts a new session preset with weak topics), and a small, tasteful end-of-session celebration (<= 1.2 s, skipped under reduced motion). Save the summary to history (localStorage) visible on the Practice home.
I6. **Model usage within the free tier.** Use the existing Groq client/route; one call per feedback, one per follow-up decision (or combine), compact prompts; per-session cap (e.g. 30 calls) with a clear message; daily cap via the existing guard. Mock everything in tests.
I7. **Tests and QA.** Vitest: bank loader/filters/license metadata present, session engine (no repeats, auto-end at N questions and at N rounds, early stop, follow-up limits, adaptive difficulty, resume after reload), intel fallback, API route caps. Playwright (`qa/v3-interview-*.mjs`, mocked `/api/interview` and `/api/intel`): setup -> 5-question session across 3 round types (coding with the Python runner, behavioral, SQL) with follow-ups -> auto-ends -> summary; a second run that ends early; shots at 1440 and 390, light and dark, of: setup, company research card, coding question (wide layout), follow-up, feedback, progress bar mid-session, end confirm, summary with celebration end state, history.
